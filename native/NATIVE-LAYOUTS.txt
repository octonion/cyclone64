Native generic memory layout experiment (2026-11-14)
==================================================

Enable explicitly with --native-layouts. This is a whole-program calling
convention: do not mix standard-library/compiler objects generated with and
without it. The default remains the previous bootstrap convention until the
remaining failures are fixed and the new convention is fully validated.

Boxed type parameters gain an unsigned-long memory-width argument. Generic
values still use canonical register words; references retain their original
native C addresses. Loads/stores use memcpy at the actual width (4-byte int,
8-byte long/pointer), and fat-pointer bounds/stride and allocations use that
same width. Nested and escaping references preserve object identity. Generic
stack arrays currently reserve word-sized storage but initialize/use a packed
prefix and expose the logical sizeof; this storage policy needs further audit.

First-class instantiations bind layout arguments in libffi closures. Static
function initializers use generated wrappers with registered bound arguments.
Closure cache keys include bound arguments, including when re-adapting a
callback. The native C open_region implementation has a separate entry point
selected by CYC_NATIVE_LAYOUTS in generated C. Existing runtime ABI is retained.

Verified checkpoints:
- layout-seed5: compiler built without the new calling convention, can emit it.
- layout-full3, layout-full4: complete 81-source compiler/stdlib native builds.
- layout-full3 runs all 16 existing native checks and the upstream suite.
- layout-asan1: all compiler/stdlib sources instrumented with Clang 21
  ASan/UBSan/function; 7 generic regressions plus a non-char zero-terminated
  pointer regression pass, including exact malloc-backed runtime redzones.
- Upstream suite passes with the instrumented translator/compiler/stdlib and
  production BDW-GC runtime. BDW-GC disables ASan fake stacks as documented in
  STATUS.txt; malloc-backed probes retain them. Leak checking remains enabled.
- Bound callback unit covers 4/8-byte captures, multi-parameter captures,
  adaptation round trips, cache discrimination, and static wrapper identity.
  Normal and live-cache runs pass; the deliberate 73-byte leak is detected.

Commands are retained in native/bootstrap/<stage>/commands.json and
native/compiler-tests/<run>/commands.json. Relevant logs:
  native/logs/layout-asan-generic.log
  native/logs/layout-asan-upstream.log
  native/logs/layout-native.log
  native/logs/layout-callback-unit.log
  native/logs/layout-callback-cache.log
  native/logs/layout-callback-leak.log

Not yet satisfactory:
- generic-existential-reference.cyc fails: unpacking a hidden boxed type does
  not restore its layout. Unknown layouts currently emit zero, which rejects
  actual dereferences instead of guessing word width. Struct construction and
  pattern unpacking must carry the metadata before this is enabled by default.
- layout-full3 vs layout-full4 agrees for 80/81 generated C files. printf.c
  differs in one bounds-check elimination decision and consequent temp names.
  Repeating printf translation with layout-full4 produces the other variant.
  Do not claim deterministic convergence for the new convention yet.
- Wider audit still includes nested arrays/aggregate memory layout, external C
  generic declarations, bound callback signatures and existing unsupported
  callback ABI cases (variadic/union/bitfield/int128 conversions).

The earlier native/experimental/polyref wrapper prototype remains isolated.
The implemented approach keeps native addresses and reifies widths instead.

Callback page-boundary correction:
The first sanitizer self-bootstrap found a libffi static trampoline exactly at
an executable page boundary. Clang's indirect-function check reads eight bytes
before the target, which faulted when the preceding page was unmapped. Runtime
allocation now reserves these first entries and exposes later entries on the
same page, retaining libffi's original writable/code addresses. Reserved slots
are freed on explicit shutdown and registered as live LSan roots while held.
No sanitizer is disabled. A 2,048-closure stress check verifies safe placement,
correct bound calls, shutdown and live-cache leak handling. The deliberate
73-byte leak is still detected. layout-asan3 then completed all 81 source
translations and linked under the fully instrumented layout-aware compiler.
Logs: layout-closure-page-*.log, layout-asan3.log. Original failure is preserved
in native/bootstrap/layout-asan2/library/compiler/tcdecl-translate.log.
Reference: https://github.com/libffi/libffi/blob/v3.5.2/src/closures.c
and https://github.com/libffi/libffi/blob/v3.5.2/src/x86/ffi64.c
