Cyclone64 / Banshee64 current status
===================================

Development candidate for GNU/Linux x86-64 (LP64). The source bootstrap must
converge across 81 generated C files. GCC and Clang are supported C backends;
GCC preprocessing is required for libc binding generation.

Compatibility review changes:
- Driver failures report the subprocess and signal; normal exit codes survive.
- Nested generic aggregate cache keys are normalized before comparison; boxed
  fields preserve word storage inside abstract-memory specializations.
- Tuple/structure callback signatures recover emitted aggregate definitions.
- Integer unboxing and explicit pointer narrowing use a pointer-width integer.
- C pthread creation uses a monomorphic ABI and collector-aware thread creation.
- Heap, region and reap byte arithmetic is native width with checked overhead.
- numelts is unsigned long; strlen/strcmp keep full incoming buffer extents.
- Array allocation temporaries and generated comprehension loops are wide;
  ordinary source comprehension indices retain their historical int width.
- All top-level historical applications run, with one precise expected failure.

Known remaining limits:
- structarray.cyc: existential array valueof lowering fails (APPLICATIONS.txt).
- Adapted variadic/union/bitfield/int128 callbacks remain unsupported.
- The proof engine is 32-bit; wide cases use runtime checks.
- Historical container/string routines with narrow counts still need auditing.
- Banshee region allocations retain their near-2-GiB per-object cap; checkpoints
  require trusted input and the same build/ABI. Custom codecs are not automatic.
- Callback cache lookup is linear and mutex-protected; shutdown needs quiescence.
- Cyclone objects must be smaller than PTRDIFF_MAX, including allocation overhead.
- BDW-GC allocations are not ASan-redzoned; malloc-backed tests supplement them.

Current commands and logs are under the selected BUILD directory. Historical
workstation paths and prior validation snapshots are in HISTORY.txt and
HISTORICAL-VALIDATION.md. See README.md for build/install usage.
