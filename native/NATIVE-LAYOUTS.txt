Native LP64 generic layout convention
====================================

Source-built Cyclone64 now defaults to native layouts. --native-layouts remains
an explicit spelling; --legacy-layouts selects the bootstrap-only convention.
The tracked stage0 compiler retains its old convention. Rebuild every compiler,
standard-library and application object together when changing conventions.
Generated native C defines CYC_NATIVE_LAYOUTS for the matching runtime entry points.

Boxed type parameters carry an unsigned-long memory-width argument. Generic
values use canonical register words; references retain native C addresses.
Loads/stores use memcpy at the actual width (4-byte int, 8-byte long/pointer).
Allocation, sizeof, pointer strides and bounds use the same logical width.
Nested and escaping references preserve address identity.

Generic stack and aggregate arrays reserve erased word capacity and use a packed
logical prefix. Nested rows use logical strides. Array-member lowering preserves
the original aggregate's storage. Static aggregate int arrays pack their constant
32-bit values into the reserved LP64 words; pointers and long values occupy a
whole word. This is a native compiler convention, not a portable serialized format.

Generic pointer fields distinguish declared erased C storage from instantiated
views. Reads and initializers use explicit casts; assignments and address-taking
preserve a typed lvalue view. Generated C requires -fno-strict-aliasing, as used
by all native build/test drivers. Datatype constructors and pattern projections
also need explicit storage/view conversions.

Existential structures and tagged unions carry width witnesses. Tagged-union
members retain a leading tag followed by common width metadata and their value.
Construction, pattern unpacking, copying and repacking preserve the witnesses.
Generated witness field names avoid source-name collisions. Untagged existential
values can be constructed and copied; unpacking their patterns was already
unsupported in the historical ILP32 language implementation.

First-class generic instantiations bind widths through libffi closures. Static
initializers use generated wrappers with registered bound arguments. Closure
cache keys include widths, including subsequent adaptation. Native C open_region
has a matching entry point. Concrete C struct arguments/returns and supported
bound callbacks invoked from C have dedicated interoperability tests.

Libffi page-boundary entries are reserved because Clang's function sanitizer
reads a prefix before an indirect target. The remaining entries preserve libffi's
original writable/code addresses. Reserved entries and active closures are live
LSan roots while cached and are freed on explicit shutdown. The 2,048-closure
stress test, live-cache test and deliberate 73-byte leak control remain logged.
No function sanitizer is disabled. Adapted variadic/union/bitfield/int128 callback
signatures that cannot be represented are rejected.

The arithmetic prover still uses 32-bit terms. Wide arithmetic is opaque to it;
fat-pointer bounds and wide-index checks remain at runtime. This deliberately
trades some check elimination for correct LP64 behavior. Runtime indexing checks
the final address, including accesses through temporarily biased cursors, and
validates wide extents before narrowing or multiplying.

See STATUS.txt for the current candidate stage names, validation and scope. Each bootstrap/test directory retains exact commands, generated C and logs;
earlier failed checkpoints are diagnostic evidence, not current success claims.
